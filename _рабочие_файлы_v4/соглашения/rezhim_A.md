# Режим А. Текст пишет модель-агент (по источникам, строго по методу)

**Действует ядро:** `Метод_изложения_v4.md`. Этот файл задаёт только роли и порядок работы; правила текста здесь не повторяются.

**Суть режима.** Из источников проекта агент берёт теорию — то, что верно (определения, факты, результаты, условия), как спросили бы на экзамене. Построение текста — порядок, переходы, все выводы — агент делает сам, строго по ядру. Если вывода нет ни в одном источнике, агент строит его сам, проверяет, исправляет и повторяет, пока вывод не пройдёт (правила — ядро, «Источники и построение выводов»).

## Роли

- **Агент:** составляет реестр, скелет, пишет текст, строит и проверяет выводы, проверяет полноту, составляет служебный список.
- **Автор:** проверяет результат. По желанию — сначала принимает скелет, потом агент пишет текст.

## Порядок работы на одну главу

1. **Тема и источники.** Какая глава, какие источники проекта по ней, какой из них основной (по инструкции проекта; если не указан — выбрать, назвать в служебном списке и зафиксировать как посылку). Если по теме нет источника — сказать об этом и остановиться (ядро: «согласованность с источниками»).
2. **Извлечение содержания.** Пройти источники по теме и выписать (для себя, не в текст): определения, данности, закономерности, результаты и условия их применимости, со ссылками на места. Порядок источника не переносится.
3. **Реестр** (ядро, шаг 0 хребта): параметры, данности, первичные понятия.
4. **Ведущий вопрос и вопросный скелет** (ядро, шаги 1–2). Агент сам проверяет скелет тестом наивного читателя и тестом пересказа (шаги 3–4). Скелет считается принятым после этой самопроверки; если автор просил принимать скелет сам — выдать его автору и ждать.
5. **Текст по шагам скелета.** Каждый шаг — ответ на свой вопрос, заканчивается названной нехваткой. Пункты 6–7 выполняются внутри каждого шага: выводы шага строятся и проверяются до перехода к следующему шагу.
6. **Выводы.** Для каждого результата: есть ли вывод в источниках. Есть — изложить его по ядру своими словами. Нет — построить по ядру («Источники и построение выводов»).
7. **Проверка каждого построенного вывода** до включения в текст — по ядру («Источники и построение выводов»). Не прошёл — исправить и проверить заново; цикл повторяется, пока вывод не пройдёт или не будет признан непостроенным (тогда — по ядру, без подгонки).
8. **Проверка полноты.** Всё содержание источников по теме из шага 2 — в тексте или исключено с причиной.
9. **Самопроверка всей главы** по чек-листу ядра и критерию готовности. Найденное — исправить (дефект перехода чинится скелетом, а не словами).

## Что выдаёт агент

1. **Текст главы** — чистый, по ядру, без служебных пометок.
2. **Служебный список** (отдельно):
   - выводы, построенные не по источнику: на каких допущениях; где в источнике стоит результат, к которому они пришли; как проверены;
   - непостроенные выводы (результат стоит «по источнику»);
   - что из источников исключено и почему;
   - основной источник, если его выбрал агент (а не инструкция проекта);
   - расхождения между источниками и какое определение выбрано как посылка.

## Правила работы с источниками

По ядру: раздел «Источники и построение выводов» (проверка по тексту источника, свои знания — только для построения вывода, запрет подгонки, полнота, служебный список, реестр отвергнутых вариантов).
